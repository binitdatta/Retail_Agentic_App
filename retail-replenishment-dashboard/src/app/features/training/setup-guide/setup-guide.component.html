7. Setup Guide — Zero to Running End to End

Build and run the complete Retail Replenishment Agentic AI POC locally: MySQL 8, Keycloak, RabbitMQ, Spring Boot, Angular, Python LangGraph, and Anthropic — in the correct dependency order.

Follow the Setup Order

The order matters because each application depends on infrastructure established by the previous layer.

Order Component Why it comes here
1 MySQL 8 Provides the schema and seed data required by Spring Boot.
2 Keycloak Provides identity, clients, roles, and JWT issuance.
3 RabbitMQ Must be available before Spring Boot initializes messaging infrastructure.
4 Spring Boot API Both Angular and the Python agent depend on the secured backend.
5 Angular Dashboard Calls the Spring Boot API and authenticates against Keycloak.
6 Python Agent Runs last because it calls the backend and may invoke Anthropic.

What depends on what?

Infrastructure

MySQL + RabbitMQ

Persistent state and asynchronous messaging must exist before the business API starts.

Identity

Keycloak

Provides JWTs required by both human and machine clients.

Business API

Spring Boot

Depends on infrastructure and becomes the API used by both Angular and Python.

Clients

Angular + Agent

Consume the secured business capabilities exposed by Spring Boot.

B. Install everything on a Mac

Homebrew provides the majority of the local development tooling. Keycloak is run separately from its standalone server distribution.

If Homebrew is not already installed: 

/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# Core tooling
brew install git openjdk@21 maven node python@3.12

# Database and messaging
brew install mysql
brew install rabbitmq

# GUI development tools
brew install --cask intellij-idea-ce
brew install --cask pycharm-ce
brew install --cask webstorm
brew install --cask mysqlworkbench

brew services start mysql
brew services start rabbitmq

Download and extract the Keycloak server distribution. From the Keycloak installation directory: 

bin/kc.sh start-dev
Development only:
start-dev intentionally relaxes production hardening and is appropriate for this local POC environment. 

mysql --version
rabbitmqctl status
node -v
npm -v
java -version
python3 --version

curl -sS http://localhost:8080/realms/master | head -c 100

C. Create and populate the database

V1 — Schema

Creates the complete MySQL relational schema. 

V1__init_retail_replenishment_schema.sql

V2 — Demo Data

Loads realistic local POC data including stores, SKUs, suppliers, low-stock conditions, and demonstration paths. 

V2__seed_test_data.sql
Run the database scripts in order 
SOURCE /path/to/V1__init_retail_replenishment_schema.sql;
SOURCE /path/to/V2__seed_test_data.sql;

Verify the seed data 

SELECT * FROM vw_low_stock_inventory;

The initial seed should return 5 low-stock rows. These records provide the starting workload for the agent.

Reset guidance:
If you need to reset demo data, truncate tables in reverse dependency order — children before parents — with foreign-key checking temporarily disabled, then re-run V2. Do not blindly re-run V1 against an existing schema.

D. Create the Keycloak realm

http://localhost:8080/admin

Log in using the Keycloak administrator account created during initial server setup.

From the realm selector choose Create realm, then import: 

retail-replenishment-service/
└── keycloak/
    └── retail-replenishment-realm.json

Navigate to: 

Clients
→ retail-replenishment-agent
→ Credentials

Keep the imported development value or regenerate the client secret and use the resulting value wherever the Python agent authenticates to Keycloak.

Navigate to: 

Clients
→ retail-replenishment-dashboard
→ Settings

Confirm the local Angular application is allowed: 

http://localhost:4200/*

If the dashboard login fails with: 

invalid_scope

the imported realm may be missing the standard profile and/or email client scopes expected by the dashboard.

Run the supplied fix_keycloak_scopes.sh utility to create and assign the missing scopes correctly.

G. Run the Python agent third

The agent runs last because it needs Keycloak for machine authentication, Spring Boot for business operations, and Anthropic for the configured judgment stages.

Prepare the Python environment 
cd retail-replenishment-agent

python -m venv .venv
source .venv/bin/activate

pip install -r requirements.txt

cp .env.example .env

Configure: 

KEYCLOAK_CLIENT_SECRET=<your-local-client-secret>
ANTHROPIC_API_KEY=<your-api-key>

Dry Run 

python -m agent.main --dry-run

Exercises the reasoning pipeline without creating production-like transactional side effects.

Real Run 

python -m agent.main

Executes the actual agent workflow against the secured Spring Boot API and persistent business state.

H. Test end to end and confirm it is working

Do not judge system health from one application starting successfully. Follow one business scenario across every architectural layer.

Obtain a service-account token: 

curl -X POST \
  http://localhost:8080/realms/retail-replenishment/protocol/openid-connect/token \
  -d grant_type=client_credentials \
  -d client_id=retail-replenishment-agent \
  -d client_secret=<secret>

Then call the Spring Boot API: 

curl http://localhost:8087/api/inventory/low-stock \
  -H "Authorization: Bearer <access_token>"
Expected starting result: 5 low-stock items.

Log into the Angular dashboard and open Inventory. The same low-stock inventory returned by the Spring Boot API should appear in the UI. 

python -m agent.main --dry-run

Verify that low-stock items are analyzed and decision stages complete without creating actual orders or escalations. 

python -m agent.main

Refresh the Angular Agent Runs screen.

A new run should appear and progress through its execution lifecycle.

If the agent creates a RECOMMENDED order:

  1. Log in as priya.manager.
  2. Open Orders.
  3. Set the Acting as value.
  4. Approve the recommended order.
  5. Inspect Spring Boot logs for the supplier-integration event.

The delivery lifecycle should progress through:

Sequence Status
1 DEPARTED
2 IN_TRANSIT
3 OUT_FOR_DELIVERY
4 DELIVERED

After delivery and receiving logic updates inventory, revisit the low-stock screen. A successfully replenished SKU should no longer appear as low stock.

Open the completed agent run and inspect:

Token usage Should show non-zero usage when LLM calls were executed.
Estimated cost Should reflect the recorded model calls.
Decision trace Should contain reasoning output for judgment stages.
LLM calls Should be correlated with the same agent run.

End-to-end verification matrix

Layer What to verify Evidence
MySQL Schema and seed data exist. Low-stock view returns expected data.
Keycloak Human and service-account authentication work. JWT access token successfully issued.
Spring Boot Secured API responds correctly. Authorized call returns low-stock records.
Angular Browser login and API display work. Inventory and Agent Run screens display backend state.
Python Agent LangGraph pipeline completes. Agent-run and decision records appear.
Anthropic Judgment calls succeed. LLM log contains usage and response information.
RabbitMQ Published events reach consumers. Supplier, delivery, or escalation listener activity appears.
HITL Manager operations work. Order approval or escalation resolution changes persisted state.

Troubleshooting by layer

Debug the layer that first fails rather than treating the whole system as one undifferentiated application.

Symptom Start here
Spring Boot cannot start because of schema mismatch MySQL DDL and JPA entity mappings
401 Unauthorized Keycloak token, issuer, expiry, or Authorization header
403 Forbidden Keycloak realm roles and Spring Security authorization
Angular login loops PKCE flow, route guard, callback, and redirect URI
invalid_scope Keycloak client scopes
RabbitMQ listener sees stale database state Verify event publication occurs after transaction commit
Agent cannot authenticate Agent client ID, client secret, Keycloak realm, and token endpoint
LLM judgment stage fails Anthropic API key and Python agent configuration
Setup Architecture Takeaway

This startup sequence mirrors the dependency structure of the architecture itself.

Infrastructure and identity come first. The secured business application comes next. Human and autonomous clients then sit on top of that enterprise foundation.

This is very different from starting with an LLM and then trying to bolt security, persistence, transactions, and messaging onto it later.

Build the enterprise foundation first; then allow AI agents to operate safely through those governed capabilities.
