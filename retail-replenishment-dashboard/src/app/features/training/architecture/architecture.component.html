Architecture Overview

The architecture deliberately separates identity, deterministic business logic, agent reasoning, persistent state, asynchronous processing, and external LLM inference. This separation keeps the AI layer from becoming the system of record or the security authority.

Architecture at a glance

Identity

Keycloak

Central trust anchor for authentication, OAuth2/OIDC, JWT issuance, and realm-role authorization.

User Experience

Angular Dashboard

Human-facing SPA used to monitor inventory, agent runs, orders, escalations, and HITL approvals.

Agent Orchestration

Python LangGraph Agent

Executes the multi-stage replenishment workflow, calls enterprise APIs, and invokes Anthropic when judgment is needed.

Business System

Spring Boot API

Secure OAuth2 resource server containing deterministic business logic, authorization, persistence, and event publication.

The core components

Each major technology in the POC has a deliberately narrow responsibility. No single component is allowed to become responsible for identity, AI reasoning, persistence, orchestration, and business rules at the same time.

Component Architectural Role Responsibility
Keycloak Identity Provider The only component responsible for authenticating users or service accounts. It knows about passwords and client credentials and issues short-lived JWT access tokens containing realm roles. Downstream applications trust the token rather than implementing authentication independently.
Angular Dashboard Human-facing Client Browser SPA used by business users and managers. A human authenticates through Keycloak using OAuth2 Authorization Code + PKCE, then uses the application to view agent runs, inventory, orders and escalations, and participate in human-in-the-loop decisions.
Python LangGraph Agent Agent Orchestrator Runs without an interactive human session. It authenticates through Keycloak using client_credentials, executes the replenishment decision pipeline, calls Spring Boot APIs as tools, and invokes Anthropic for narrowly defined judgment tasks.
Spring Boot API Secure Business Hub The authoritative application service. It operates as an OAuth2 Resource Server, validates JWTs, enforces endpoint-level roles, executes deterministic business rules, accesses repositories, controls transactions, and publishes business events.
MySQL 8 System of Record Holds persistent business state including inventory, stores, suppliers, replenishment orders, escalations, agent execution records, audit information, and supporting reference data.
RabbitMQ Asynchronous Event Bus Decouples transactional API operations from asynchronous side effects. Business events can trigger downstream activity without making the original HTTP request wait for every consumer to complete.
Anthropic External LLM Service Provides model inference for selected reasoning and judgment steps. It does not authenticate users, query MySQL directly, publish RabbitMQ events, or act as the system of record.

Two clients, two OAuth2 grants

A central architectural principle is that the human-facing dashboard and the autonomous agent are two fundamentally different types of OAuth2 clients.

Client Actor OAuth2 Grant Why Calls
Angular Dashboard Human User Authorization Code + PKCE A user is actively authenticating through a browser. PKCE protects the authorization-code exchange without requiring the SPA to hold a client secret. Spring Boot REST API
Python Agent Service Account client_credentials There is no interactive human login. The agent authenticates as a machine identity and receives its own access token. Spring Boot REST API

Supporting components

RabbitMQ — asynchronous processing

RabbitMQ separates synchronous REST processing from operations that can safely happen later.

For example, creating an order should not require the original API request to remain open while every downstream supplier or delivery simulation task completes.

Important transaction lesson: publish the event only after the database transaction has committed.

This POC exposed a real concurrency problem when an event was published before the transaction creating the corresponding database state had committed. A consumer could receive the event immediately and read stale data.

Implementation responsibility: EventPublisher

Anthropic — isolated model inference

Anthropic is intentionally isolated from the rest of the infrastructure. The LLM receives only the context necessary for the judgment being made.

In this POC, the agent uses LLM reasoning for selected decisions such as:

  • replenishment order recommendation
  • escalation severity assessment
The LLM does not directly know how to connect to Keycloak, MySQL, RabbitMQ, or the Angular application. Provider or model changes therefore remain isolated from the rest of the enterprise architecture.

Request flow — end to end

The following sequence shows how a user request and an autonomous agent execution move through the architecture.

A business user opens the Angular dashboard.

Angular initiates an OAuth2 Authorization Code + PKCE flow. The browser is redirected to Keycloak, the user authenticates, and the browser returns to Angular with the authorization result. Angular ultimately obtains an access token representing that user.

Angular sends the Keycloak-issued access token on API requests: 

Authorization: Bearer <access-token>

Spring Boot does not ask Angular for a username or password. It validates the signed JWT and authorizes the request according to the roles carried by the token.

The Python agent does not reuse the human user's session. It authenticates independently using its own Keycloak service account. 

grant_type=client_credentials

Keycloak returns a JWT representing the agent's machine identity and authorized roles.

The agent orchestrates the business workflow rather than directly manipulating database state.

Stage Purpose
1. Detect Identify inventory conditions requiring attention.
2. Forecast Evaluate demand and replenishment need.
3. Supplier Check Determine whether supply can satisfy the requirement.
4. Recommend / Escalate Choose whether an order can proceed or requires human review.
5. Order Create the approved replenishment order through the API.
6. Monitor Track downstream delivery progress and exceptions.

Every API call passes through the Spring Security OAuth2 Resource Server security boundary.

  • validate JWT signature
  • validate issuer and token validity
  • extract roles
  • enforce endpoint authorization
  • execute deterministic business rules
  • persist state to MySQL
  • produce business events when required

Business operations can publish events after durable state has been committed successfully.

Example Event Possible Consumer Action
order-created Supplier integration processing
inventory-updated Re-evaluate stock state
escalation-raised Notification or human-review workflow
delivery-status-changed Update order and delivery state

The dashboard reads the resulting state through the same secured Spring Boot APIs. Users therefore see persisted business outcomes: agent decisions, inventory state, orders, escalations, LLM usage, and execution history rather than transient state maintained by the LLM itself.

Key architectural principles

1. Identity stays centralized

Applications do not reimplement login or password validation. Keycloak remains the source of truth for identities and access tokens.

2. AI does not own business state

LangGraph can reason and orchestrate, but authoritative state changes occur through secured Spring Boot services and are persisted to MySQL.

3. The LLM is replaceable

Anthropic is treated as an isolated reasoning dependency rather than an infrastructure component embedded throughout the application.

4. Security is enforced server-side

The Angular application can improve UX based on roles, but Spring Boot remains responsible for actual authorization enforcement.

5. Events follow committed state

Asynchronous processing must not observe state that has not yet been durably committed by the originating transaction.

6. Humans remain in the loop

Agent automation can stop at controlled approval boundaries when a business decision requires human review.

Architecture takeaway

This POC does not treat the LLM as the application.

Instead, the AI capability sits inside a conventional enterprise architecture with explicit identity, API, persistence, messaging, authorization, transaction, and human-control boundaries.

Two client types, two OAuth2 grants, one identity provider, one secure business API, one durable system of record, and an AI agent operating within those boundaries.
