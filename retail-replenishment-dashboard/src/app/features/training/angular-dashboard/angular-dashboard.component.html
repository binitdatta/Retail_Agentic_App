Angular Project Overview
Project

retail-replenishment-dashboard

This application is the human-facing interface for the Retail Replenishment Agentic AI POC.

It allows authenticated users to inspect autonomous agent activity, review replenishment orders, work shortage escalations, monitor low-stock inventory, and perform Human-in-the-Loop actions.

The Angular application does not own authoritative business state. It obtains data and performs actions through the secured Spring Boot API.

Standard structure of a modern Angular application

Angular does not force every project to use the exact same folder layout, but a scalable standalone application commonly separates application-wide infrastructure from business features and reusable models.

Location Responsibility Typical Contents
src/app/core/ Application-wide infrastructure Authentication, HTTP interceptors, route guards, singleton services, API clients, PKCE utilities, global state helpers.
src/app/features/ Business capabilities Route-oriented features such as Orders, Inventory, Agent Runs, Escalations, Training, and Authentication Callback.
src/app/models/ TypeScript domain contracts Interfaces and types describing API requests, API responses, orders, inventory, escalations, agent runs, and related structures.
src/app/shared/ Reusable UI building blocks Shared components, pipes, directives, utility widgets, reusable tables, badges, dialogs, and presentation helpers. Your current project may add this later if reuse grows.
src/environments/ Environment-specific values API URLs, Keycloak base URLs, realm names, client IDs, and environment-specific configuration.
public/ Static files Images, icons, downloadable files, training diagrams, and other files copied as static build assets.
src/styles.scss Global styling Global Bootstrap overrides, application colors, navbar styling, training-page styles, cards, tables, code blocks, and shared layout rules.
src/main.ts Application bootstrap Starts the Angular application and typically calls bootstrapApplication() for a standalone app.
app.config.ts Application providers Global dependency-injection providers such as routing, HTTP client configuration, interceptors, and related standalone application configuration.
app.routes.ts Routing configuration Defines application routes, lazy feature loading, route guards, dynamic route parameters, and training pages.
app.component.ts Root Angular component Application shell containing the top navigation, router outlet, global layout, and other root UI behavior.

The core/ package

File Role

Authentication with Authorization Code + PKCE

The dashboard implements Authorization Code + PKCE using the browser's Web Crypto API through core/pkce.util.ts and core/auth.service.ts.

login() generates a random PKCE code verifier.

The browser hashes that verifier using SHA-256 and produces the code challenge. 

code_challenge_method=S256

Angular redirects the browser to Keycloak's authorization endpoint.

The code challenge travels with the authorization request, but the original verifier remains with the browser.

After authentication, Keycloak redirects the browser to: 

/callback

The redirect contains the short-lived authorization code.

handleCallback() sends the authorization code and the original verifier to Keycloak's token endpoint.

Keycloak validates that the verifier corresponds to the earlier SHA-256 challenge.

The returned access_token and id_token are stored in sessionStorage.

Secured API calls use: 

Authorization: Bearer <access_token>

logout() invokes Keycloak's logout endpoint and supplies: 

id_token_hint=<id_token>

Without the required logout context, Keycloak can reject the logout request rather than ending the SSO session correctly.

Two authentication bugs worth teaching

1. Async route-guard redirect loop

The route guard must respect the asynchronous nature of PKCE generation.

Calling auth.login() without awaiting the cryptographic work and then immediately returning another redirect can trigger a navigation loop.

A visible symptom is a Network tab filled with repeated canceled Keycloak authorization requests.

2. Access-token expiry

Successful initial authentication does not solve the complete session lifecycle.

Access tokens expire. The HTTP layer therefore needs to recognize authentication failures and route the user back through the authentication flow.

Without this behavior, screens eventually degrade into generic API errors after the token expires.

Guard versus interceptor

Component When it runs Responsibility
authGuard During Angular navigation Prevents unauthenticated users from entering protected application routes.
auth.interceptor During outgoing / incoming HTTP processing Attaches the access token to API calls and provides a centralized point for handling authentication-related HTTP failures.

API service pattern

Feature components should not scatter raw HTTP URLs and request construction throughout the application.

api.service.ts provides a central integration boundary between Angular and the Spring Boot backend.

Architectural benefit:
UI components focus on presentation and interaction while the API service owns transport-level communication with the backend.

Human-in-the-Loop screens

The dashboard contains both read-only observability pages and screens where an authorized manager can intervene in agent-driven workflows.

Feature Human Action Security Intent
Replenishment Orders Approve or cancel an order Manager decision over recommendations not automatically executed by the agent.

Shortage Escalations Resolve escalation Manager records a resolution note and closes the exception.
Inventory Read only Provides visibility without creating an alternate mutation path.

Frontend role checks are not a security boundary

The Angular application reads realm_access.roles from the JWT so the UI can adapt to the authenticated user.

For example, a read-only viewer should not be shown a button that invokes a manager-only operation.

But hiding that button does not secure the operation.

The real authorization boundary is Spring Boot.
Even if a user manually constructs the HTTP request, the API independently validates the token and required role.

ActorNameService and audit context

"Acting as"

ActorNameService maintains a small session-scoped display identity.

The value is visible in the navigation bar so the user does not have to re-enter it for every HITL action.

HITL audit context

Manager actions such as order approval and escalation resolution can carry meaningful human context alongside the authenticated identity.

Escalation resolution additionally requires a short note before submission.

This separates authentication identity from the human-readable operational context presented in the demo.

End-to-end browser request flow

Step Component What happens
1 Angular Router User navigates to a protected feature route.
2 authGuard Confirms that an authenticated session exists.
3 AuthService / Keycloak If necessary, redirects through Authorization Code + PKCE.
4 Feature Component Requests data through the application's API abstraction.
5 HTTP Interceptor Adds the Bearer access token to the backend request.
6 Spring Boot API Validates the JWT, checks roles, and executes business logic.
7 Angular Component Renders the resulting authoritative API state.

Key Angular design principles in this POC

1. Organize by feature

Business capabilities such as orders, inventory, escalations, and training are independently organized.

2. Keep cross-cutting logic in core

Authentication, route guards, API access, PKCE, and interceptors are centralized rather than duplicated.

3. Use standalone components

Modern Angular configuration reduces dependence on large centralized NgModule structures.

4. Treat the API as authoritative

Angular displays and requests business state but does not become the authoritative business system.

5. Security stays server-side

UI role checks improve usability, while Spring Boot remains responsible for actual authorization.

6. Authentication has a lifecycle

Login, callback handling, API token propagation, expiration, and logout all require explicit design.

Angular responsibility boundaries

Concern Primary Owner Explanation
Screen rendering Angular Components render application state and user interactions.
Browser routing Angular Router Maps URLs to standalone feature components.
Human login initiation Angular + Keycloak Browser initiates Authorization Code + PKCE.
Credential verification Keycloak Angular does not validate user passwords.
JWT transport Angular HTTP layer Sends the access token with secured API requests.
JWT validation Spring Boot The backend validates the Keycloak-issued token.
Business authorization Spring Boot Backend role checks determine whether an action is allowed.
Authoritative state Spring Boot + MySQL The browser displays state but does not become its system of record.
Angular architecture takeaway

The Angular dashboard is the human interaction layer of the Agentic AI system.

It handles navigation, presentation, PKCE browser authentication, API integration, session behavior, role-aware user experience, and Human-in-the-Loop interactions.

But it deliberately does not become the security authority, business-logic authority, or system of record.

Angular provides the experience; Keycloak establishes identity; Spring Boot enforces business security; MySQL preserves authoritative state.
